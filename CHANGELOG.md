# Changelog
- 2026-10-18: Initial public version with pictures, navigation, list/grid view.
- 2026-10-18: Served as a full HTML document (standards mode, charset, mobile viewport) plus SEO: description, canonical, Open Graph, JSON-LD, sitemap.xml, noscript text. Research: Google indexes JS-rendered pages but needs these tags and a sitemap to understand them.
- 2026-10-18: Added a social share preview image (og.png) so links shared in chats and social posts show a picture. Research: pages with a 1200x630 image get larger, more clickable previews.
- 2026-10-18: Added a "Not for me" button on every artist (saved in the browser, with Undo and a "show hidden artists again" link). Research: music-discovery users complain about repeats and things they already know, and ask to block or dismiss items.
- 2026-10-18: Find-similar results now have a shareable link (#like=ID) and a "Copy link to these results" button; opening a link shows those results. Research: Bandcamp pages feel like disconnected islands, while Music-Map is praised for simple, passable results.
- 2026-10-18: Added "Order results by: Closest match / Smallest first" on Find similar (remembered in the browser). Research: users ask for a discover-vs-familiar control, and a study found recommendations are least accurate for fans of beyond-mainstream music.
- 2026-10-18: Added "Hide <genre> from All genres" (and a way to show hidden genres again), remembered in the browser. Research: Spotify users say new-release lists are crowded with genres they don't like and ask for a "play less of this genre" control.
- 2026-10-18: Added an "Autoplay next" toggle for previews: when a 30-second preview ends, the next artist in the list starts (off by default, remembered). Research: SoundCloud, YouTube Music and Spotify have all added quick-sampling preview formats because listeners want to skim many artists fast.
- 2026-10-18: Accessibility: added a "Skip to search and results" link (first Tab stop) and kept keyboard focus in the list after hiding an artist. Research: WebAIM and WCAG guidance list skip links and focus management as core keyboard-access requirements.
- 2026-10-18: Added a "Recent" row of your last 8 Find-similar searches (saved in the browser, with Clear). Research: Spotify users say they lose artists they liked when lists refresh and ask for a history to go back to.
- 2026-10-18: Shortlist upgrades: "Copy shortlist link" (opens on any device and merges the artists in, with Undo), plus a Deezer link and Remove button on each entry. Research: users complain favorites don't sync between phone and computer and ask for watch lists to check artists later.
- 2026-10-18: Added a Theme switch (Auto / Light / Dark), remembered in the browser and applied before the page paints. Research: Last.fm users install extensions just to get dark mode, and Spotify users request a light mode, so people want to choose.
- 2026-10-18: Added a Release type filter on Discover (All / Albums / EPs / Singles), remembered in the browser. Research: release-tracking apps like MusicHarbor sell filtering by release type, and singles make up about 75% of the recent releases here, so albums were buried.
- 2026-10-18: Added a "Surprise me: open a random artist" button in the page header (respects fan limit, hidden artists and hidden genres). Research: Spotify users ask for a random-music button that ignores their taste, and Bandcamp's Discoverinator was built to recreate chance finds. Note for later: the controls area is getting crowded and could be tidied.
- 2026-10-18: Added a "My page" tab: a customizable profile (name, tagline, bio, accent color, background, font, corners, links), SoundCloud player embeds for the visitor's own tracks, an "Auto-style from my taste" helper (not an AI), and a share link that opens the page read-only. Saved in the browser only; no sign-in yet. Shared links are sanitized and only soundcloud.com permalinks can be embedded. Also fixed the phone tab row so three tabs fit. Requested by the owner.
- My page v2 (requested by the owner): 12 quick looks, custom colors/gradients/patterns, 11 fonts, layouts, borders, shadows, animations, floating effects, 7 synthesized ambient sounds, click-to-enter screen, YouTube videos and looping banner video, tags, favorite artist, section reorder, side-by-side live preview, visitor view, backup/restore, compressed share links.
- 2026-10-19: Keyboard shortcuts: press / to jump to search and S for a random artist (ignored while typing and on My page). Research: Every Noise at Once fans mourn its fast, keyboard-friendly browsing after it was shut down.
- 2026-10-19: Tidied the Discover controls: only the fan-limit filter stays in view; View, Theme and Previews moved into a collapsed "Display options" section. Research: users of Bandcamp-style discovery pages say too many visible options bury the filters they actually use.
- 2026-10-19: The browser tab title now names the artist you are viewing ("Artists like X | Fresh Mic"), including when a shared link is opened, so tabs, history and bookmarks are easy to tell apart. Research: discovery users keep many tabs open while comparing artists.
- 2026-10-19: Added an "Only artists Deezer links directly" toggle on Find similar (remembered in the browser) so results can be trimmed to the closest matches. Research: Music-Map and TasteDive style tools leave users unsure how close each suggestion really is.
- 2026-10-19: Added "Download as spreadsheet (CSV)" to the shortlist (artist, Deezer fans, Deezer link; safe against spreadsheet formula text). Research: Spotify and Plex users repeatedly ask for a way to export their saved music.
- 2026-10-19: "Show more" on Find similar now says how many are left and how many are shown (e.g. "Show 24 more (24 of 71 shown)"), and keyboard focus moves to the first new result. Research: UX guidance favors a Load more button with a visible count over endless scrolling.
- 2026-10-19: On phones and tablets the results link button becomes "Share these results" and opens the device's own share sheet (Web Share API); desktop keeps "Copy link". Research: web UX guidance recommends the native share sheet on mobile with copy-link as the fallback.
- 2026-10-19: Find-similar search box now has a × clear button, and Escape closes suggestions first, then clears the text. Research: users expect a one-tap clear in search fields, especially on phones.
- 2026-10-19: Added a one-line legend under Find-similar results explaining the fan-count bars and the dark tick for the searched artist. Research: the bars were unlabeled and hidden from screen readers, so first-time visitors had to guess what they meant.
- 2026-10-19: Added "Print shortlist": prints just your numbered shortlist (artist and fan count) with all the page chrome hidden. Research: people use saved-artist lists away from the screen, for example at record shops and gigs.
- 2026-10-19: Find-similar rows now add "Latest release: <date>" when the snapshot has release data for that artist (about a fifth of rows). Research: users of release-tracking apps want recency visible without opening each artist.
- 2026-10-19: Each Find-similar result row now has a "Find similar" button, so you can hop from artist to artist and keep exploring from any result. Research: Music-Map is loved for clicking a name to re-center the map, and Bandcamp pages are criticized as disconnected islands.
- 2026-10-19: Browser Back/Forward now step through the artists you hop between with "Find similar" (each hop is its own history entry), so a chain of hops can be retraced. Research: Music-Map users explore by clicking through related names and want to get back to where they came from.
- 2026-10-19: Each shortlist entry now has a "Find similar" button (shown when the artist has related-artist data), so a saved list becomes a starting point for more exploring. Research: users of discovery tools say saved lists are dead ends they have to leave to keep digging.
- 2026-10-19: Added "Clear shortlist" (shown only when the list has artists) with an Undo that restores everything. Research: users of saved-music lists say there is no quick way to start over and fear losing a list by mistake.
- 2026-10-19: Added a "Released in the last 90 days" toggle on Find similar (remembered in the browser) that keeps only related artists with a recent release. Research: Spotify and release-tracker users say they want a way to see what similar artists have put out lately, not just who sounds alike.
- 2026-10-19: Added a third ordering on Find similar, "Newest release" (most recent release first; artists without release data go last), remembered in the browser. Research: users of Spotify and release trackers say they want to sort related artists by what is new, not only by how close they sound.
- 2026-10-19: Added "Save all shown" on Find similar: adds every result currently on screen to your shortlist in one tap (skips ones already saved), with Undo. Research: Music-Map and TasteDive users complain that saving a whole set of suggestions means clicking each one.
- 2026-10-19: Switching between Discover, Find similar and My page now returns to the top of the page instead of keeping the old scroll position. Research: users of long-scrolling discovery pages report landing mid-page after switching views and thinking content is missing.
- 2026-10-19: Added a "Released within" control on Discover (Any time / Last 7 days / Last 30 days, remembered in the browser) so the New releases list can be narrowed from six months to the last week or month. Research: release-tracker users say a six-month list is too long to check regularly and ask for a 'what came out this week' view.
- 2026-10-19: Reopening the site on the Find similar tab now brings back the artist you last searched, instead of resetting to the starter artist (a shared link still wins; first-time visitors still see the starter). Research: users of discovery tools say losing their place on a refresh or a returning visit is a top annoyance.
- 2026-10-19: The 30-second preview bar is now a seek bar: click or tap it to jump within the clip, or focus it and use the arrow keys to move 5 seconds (it also has a taller touch target and a screen-reader label). Research: Spotify and SoundCloud users complain previews can't be scrubbed, so they replay the whole clip to hear a later part.
- 2026-10-20: Previews now show the song and artist on the phone lock screen, headphones and browser media keys, with play, pause and next-track working (next jumps to the following artist's preview). Research: listeners who skim many artists want to keep going with the screen off or from earbuds, as they can on Spotify and SoundCloud.
- 2026-10-20: Pressing Esc now stops a playing preview (the footer's keyboard hint mentions it); Esc in the search box still closes suggestions and clears the text. Research: Every Noise at Once and other fast, keyboard-driven discovery tools were praised for letting people skim without reaching for the mouse.
- 2026-10-20: Release dates older than about six months now show the year (for example "Oct 24, 2025"), so "Oct 24" can no longer mean this year or last. Research: music-tracker users report undated or year-less release dates as a common source of confusion.
- 2026-10-20: Hidden gems now says how many artists match (for example "1658 match") and has a "Show 8 more (8 of 1658 shown)" button, with focus moved to the first new row; Shuffle and genre changes reset it to 8. Research: users of discovery lists dislike a fixed handful with no way to see more or know how many exist.
- 2026-10-20: Discover's New releases "Show more" now says how many are left and shown (for example "Show 24 more (24 of 3015 shown)") and moves keyboard focus to the first new row, matching Find similar and Hidden gems. Research: the same Load-more-with-a-count guidance applies to every long list, and keyboard users lose their place when focus stays behind.
- 2026-10-20: The fan-count limit (Any size / 500K / 100K / 25K / 5K) is now remembered in the browser, so it no longer resets to 100K on every visit. Research: users of discovery sites with filters complain that settings reset on reload and have to be re-applied each time.
- 2026-10-20: The genre chip you pick on Discover is now remembered in the browser (it falls back to All genres if that genre is no longer listed). Research: Spotify and Bandcamp users complain that genre filters reset on every visit.
- 2026-10-20: Search suggestions now bold and underline the part of each name that matches what you typed (set as plain text, so typed HTML is never interpreted). Research: users expect type-ahead lists to show why each result matched, as Google and Spotify do.
- 2026-10-20: When a search matches nothing, the suggestion box now says so ("No artist matching 'xyz' in the snapshot. Try fewer letters.") and offers a "Search Deezer" link, instead of the vague "Not in the snapshot yet". Research: dead-end empty states are a top complaint about niche discovery tools; a next step keeps people moving.
- 2026-10-20: Coming soon now has a "Show 12 more (12 of 52 shown)" button; before, only the first 12 announced releases were reachable even though the heading counted all of them. Focus moves to the first new row. Research: upcoming-release lists are the main reason people return to tracker apps, and a hard cap with no way past it feels broken.
- 2026-10-20: Added a tab icon (a small blue microphone, so the site is findable among open tabs and bookmarks and no longer requests a missing favicon) and the phone browser bar now follows the theme: light, dark or your device setting. Research: users keep many tabs open while comparing artists and a blank tab icon makes the site hard to find.
- 2026-10-20: Added a "Reset filters" button on Discover that appears only when the fan limit, genre, release type or "Released within" differs from the default, and puts all four back in one tap. Research: now that filters are remembered between visits, people need a quick way out of an over-filtered or empty list.
- 2026-10-20: When Find similar has no results, the message now names the artist and offers one-tap fixes for whichever filters are on ("Show any size", "Include indirect matches", "Include older releases") instead of telling you to look for a control above. Research: dead-end empty states with no next step are a standard UX complaint, and they got likelier now that filters are remembered.
- 2026-10-20: The Find-similar heading now has a "Listen to <artist> on Deezer" link for the artist you searched, so you can hear the artist you started from while judging the matches. Research: Music-Map and TasteDive users say they often can't remember what the starting artist sounds like and have to leave the page to check.
- 2026-10-20: On touch screens the links and buttons on every result row (Play, Deezer, YouTube, Bandcamp, Spotify, Find similar, Save, Not for me) are now 40px tall instead of 18 to 29px, so they are easier to hit without mis-taps; desktop layout is unchanged. Research: WCAG 2.2 sets 24px as the minimum target size and mobile guidance recommends about 44px, and tiny adjacent links are a common phone complaint.
- 2026-10-20: The three tabs (Discover, Find similar, My page) now work like standard tabs for keyboard and screen-reader users: Left and Right arrows (and Home and End) move between them, and Tab skips the unselected ones instead of stopping on all three. Research: WAI-ARIA's tabs pattern calls for arrow-key navigation, and tab bars without it are a common accessibility audit failure.
- 2026-10-20: Relative release dates ("1 day ago") now count from today's real date instead of the day the data was captured, so they stay correct as the snapshot ages, and the footer says how old the snapshot is (for example "Snapshot: 2026-10-18 (2 days old)"). Research: stale data presented as fresh is a top trust complaint about release trackers; users want to know how current the list is.
- 2026-10-20: The browser tab title now follows the tab you are on ("Fresh Mic" on Discover, "Artists like X | Fresh Mic" on Find similar, "My page | Fresh Mic"), where before it stayed on the last artist even after you went back to Discover. Research: users keep many tabs open and rely on the title to tell them apart.
- 2026-10-20: The pop-up messages with an Undo (hide, remove, clear, save all) now stay for 10 seconds instead of 6 and pause while the pointer or keyboard focus is on them, and the Undo button has a bigger tap area. Research: WCAG 2.2 asks that timed messages be adjustable or pausable, and users say Undo toasts disappear before they can react.
- 2026-10-20: The "My shortlist" jump link on Discover now shows how many artists are saved (for example "My shortlist (3)") and updates as you save or remove. Research: saved-list features that show no count leave users unsure the save worked.
- 2026-10-20: On desktop the two search boxes now say "(press / anytime)", so the existing / shortcut is discoverable without scrolling to the footer; touch screens keep the short placeholder. Research: hidden keyboard shortcuts go unused, and Last.fm and Every Noise users ask for a visible hint.
- 2026-10-20: Added Windows High Contrast (forced colors) support: buttons get a visible border, the selected tab keeps a thick underline, the highlighted search suggestion gets an outline, and Back to top is outlined, because those cues were colour-only and disappeared. Research: forced-colors mode strips background colours, and border-less accent buttons are a common audit failure.
- 2026-10-20: Every link that opens in a new tab (Deezer, YouTube, Bandcamp, Spotify, previews) now tells screen readers "(opens in a new tab)"; nothing changes visually. Research: WCAG technique G201 asks for a warning before a link opens a new window, and screen-reader users say unannounced new tabs are disorienting.
- 2026-10-21: Find-similar results can be browsed from the keyboard: J and K move to the next and previous artist (with a visible focus ring), and P starts that artist's preview; the footer lists the keys. Research: Reddit and Hacker News users of list-heavy sites say they miss the j/k browsing they know from Gmail and Reddit.
- 2026-10-21: Pressing B on the artist you have selected with J/K saves it to (or removes it from) your shortlist; the footer lists the key. Research: the same j/k browsing users want usually comes with a one-key save, as in Gmail and Reddit tools.
- 2026-10-21: With an artist selected using J/K, X hides it (with the usual Undo) and F opens Find similar for it, next to the existing P (preview) and B (save); the footer lists all the keys. Research: power users of list-based discovery tools ask for keyboard triage so they can sort a long list without the mouse.
- 2026-10-21: Pressing ? opens a keyboard-shortcuts card (search, random, J/K, P, B, X, F, Esc), closed with Esc or its Close button, so the keys no longer need to be found in the footer. Research: ? for a shortcut list is the convention from Gmail, GitHub and Reddit tools, and users say hidden shortcuts go unused.
- 2026-10-21: "Surprise me" (and the S key) no longer repeats any of your last 40 random picks, where before it only avoided the single previous one. Research: random-music buttons (Spotify, Every Noise) are criticised for serving the same few results again.
- 2026-10-21: Pressing Z now clicks Undo while an Undo message is showing (after hiding, removing or clearing), and the shortcuts card lists it. Research: one-key undo is the Gmail and Reddit-tool convention, and it pairs with the new J/K/X keyboard triage.
- 2026-10-21: Pressing Esc now dismisses the pop-up message (Undo or notice) when one is showing; a playing preview still stops first. Research: WCAG 1.4.13 asks that content that appears on its own can be dismissed without moving the pointer or focus.
- 2026-10-21: Hovering a fan count (for example 25.2K) now shows the exact number (25,201 Deezer fans) on results and Discover lists. Research: rounded counts frustrate people comparing small artists, and Last.fm and Bandcamp users like exact numbers on demand.
- 2026-10-21: On desktop, the result row under the pointer gets a soft highlight, so you can keep your place in a long list of similar artists. Research: Last.fm and Music-Map users like clear row feedback when scanning long lists; touch screens and the grid view are unchanged.
- 2026-10-21: When you step up through results with K, the selected artist now stops below the sticky top bar instead of sliding underneath it. Research: sticky headers covering the focused item is a WCAG 2.2 "focus not obscured" failure.
- 2026-10-21: The scrolling genre chip row on Discover now fades at whichever edge has more chips hidden, so it is clear the row can be scrolled sideways. Research: horizontally scrolling chip rows with no visible cue are a common usability complaint, since people miss the genres that are cut off.
- 2026-10-21: Removed a duplicate Back to top button added on 2026-10-20 (the site already had one); only the original remains. Fix: two identical round buttons stacked in the corner.
- 2026-10-21: The long keyboard-keys sentence in the footer is now one short line with a "show shortcuts" link that opens the shortcuts card (the ? key still works), so touch and mouse users can reach it too and the footer is less cluttered. Research: long footers of fine print are rarely read; a single link to a help card is the usual pattern.
- 2026-10-21: When Discover's New releases has no matches, the message now offers one-tap fixes for the filters that are on ("Show any size", "All genres", "All types"), and the empty Hidden gems message offers "All genres", like the Find-similar empty state. Research: dead-end empty states with no next step are a standard UX complaint, and filters are now remembered between visits.
- 2026-10-21: With an artist selected using J/K, pressing O opens their Deezer page in a new tab; the shortcuts card lists it. Research: keyboard triage lists are most useful when every row action has a key, and "open" is the first one people reach for.
- 2026-10-21: When Discover reopens with a genre remembered from last time, the sideways-scrolling genre row now scrolls to show that genre instead of leaving it hidden off-screen. Research: a remembered filter you cannot see makes people think results are broken.
- 2026-10-21: If a preview can't load because Deezer is unreachable (offline, blocked or an ad blocker), the Play button now says so and a message explains, instead of the misleading "No preview". "No preview" stays for tracks Deezer really has no clip for. Research: people blame the site when a silent failure is reported as missing content.
- 2026-10-21: While a preview is playing, Space pauses and resumes it (when no button or field has focus), with a short message; the shortcuts card lists it. Research: people expect the space bar to pause audio on any player, and previously the only option was to stop and restart.
- 2026-10-21: The preview player now has its own volume slider, remembered between previews and visits (default 90%), so a loud preview no longer means reaching for the device volume. Research: sudden loud 30-second clips are a common complaint about discovery sites with autoplaying previews.
- 2026-10-21: The preview player now shows elapsed time (for example 0:15 / 0:30) under the progress bar. Research: a bare progress bar gives no sense of how long a clip is, and Bandcamp and Last.fm players both show times.
- 2026-10-21: On phones and tablets, taps on buttons, links and tabs no longer wait for a possible double-tap zoom, so they respond at once, and the page text no longer jumps in size when the phone is rotated. Research: the double-tap delay on touch browsers is a standard cause of "laggy" mobile sites.
- 2026-10-21: Search boxes, chips and option buttons now have borders dark enough to see (about 3:1 contrast against the page, up from 1.3:1) in both light and dark themes, and the desktop search hint was shortened to "(press /)" because it was being cut off. Research: WCAG 1.4.11 asks for 3:1 contrast on the edges of form controls, and faint outlines are a common complaint on pale themes.
- 2026-10-21: On desktop, option buttons, tabs, the Not for me and Find similar buttons and the accent buttons now react when the pointer is over them (border or text colour change, slight brightening), so it is clear what is clickable. Research: controls with no hover feedback feel dead on desktop, a frequent comment on minimalist music tools.
- 2026-10-22: The result that is playing a preview now gets an accent bar on its left edge, so in a long list you can see which artist the sound belongs to; it clears when the preview stops. Research: with several results on screen, listeners lose track of which row is playing (a common Spotify and Bandcamp list complaint).
- 2026-10-22: After you jump from one artist to a similar one, a "← Back to <artist>" button appears next to the heading and returns you to the previous artist (the browser Back button already did, but people on phones don't think to use it). This also fixes the first jump from the starter artist, which Back could not return to. Research: Music-Map and TasteDive users get lost after a few hops and ask for a way back through the chain.
